### Blocker found and fixed

During the first clean `npm ci`, Vitest failed with `Cannot find native binding ... @rolldown/binding-*` (npm optional-dependency
bug npm/cli#4828). Cause: an earlier `npm install --package-lock-only`, run in this pass to sync `engines`, had
dropped every platform-specific optional binding from the lockfile. That would have broken `npm ci` on the Linux CI runner too.
Fix: deleted `node_modules/` and `package-lock.json` and ran a fresh `npm install`. The lockfile now lists all 15
`@rolldown/binding-*` targets, including `linux-x64-gnu` and `win32-x64-msvc`. Every direct dependency is exact-pinned,
so no version changed. Clean `npm ci` then passed on both Node versions.

## Known limitations

- Claim extraction from prose is not implemented: wiki claim blocks are hand-written fixtures.
- The detector only knows registered predicates and explicit ordering rules: no paraphrase handling, world knowledge
  or entity resolution.
- Benchmark figures describe only the 21-claim synthetic fixture.
- The advisor replays offline fixtures only. No real model is called or evaluated.
- Single-user and file-based, with no authentication; `--actor` is a label.
- The hash chain detects but does not prevent tampering. Truncation needs an externally stored head hash. A writer with
  file access can forge a consistent chain, but cannot make `apply` write content that differs from the displayed diff
  (new test).
- A multi-page apply validates every page first but is not one atomic transaction.
- The no-network check patches Node primitives in-process; it is not OS isolation. The context experiment estimates
  tokens as chars/4.
- Tested on Windows only (Node 22.23.4 and 24.9.0); Linux/macOS untested until CI runs.
